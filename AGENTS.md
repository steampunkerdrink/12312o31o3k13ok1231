# AGENTS.md — Памятка для ИИ-ассистента

Этот файл описывает проект, архитектуру и правила работы над ним.
Читай его перед внесением любых изменений в код.

---

## 1. Что это за проект

**VK CLI Bot** (`VK Interactive CLI Bot`) — асинхронный VK-бот на Python,
который позволяет администратору управлять **интерактивной bash-сессией** прямо
из чата ВКонтакте.

- Пользователь (VK ID из списка админов) пишет команду в чат → бот выполняет её
  в общей PTY-сессии (bash) на сервере → вывод отправляется обратно в VK.
- Поддерживается **интерактивный режим** (для `ssh`, `apt`, `nano`, `mysql`,
  `ufw` и т.п.) и **обычный режим** (команда выполняется, вывод захватывается
  по маркеру окончания).

Важно: это **server-бот** (по сути remote-shell). Доступ строго
ограничен списком `ALLOWED_ADMINS`. Любые изменения должны сохранять этот контроль.

## 2. Технологический стек

| Компонент | Используется |
|-----------|-------------|
| Язык | Python **3.12+** |
| Фреймворк ВК | **vkbottle** `>=4.7.0` |
| Рендер вывода в PNG | **Pillow** `>=9.0.0` |
| HTTP/асинхронность | **aiohttp** `>=3.9.0`, `asyncio` |
| Валидация | **pydantic** `>=1.10.0` |
| Зависимости | в `requirements.txt` |
| Запуск | вручную (`python3 async_server_bot.py`) или через `systemd` |
| ОС деплоя | Linux (используется `os.openpty`, `os.setsid`, `/bin/bash`, `/root`) |

## 3. Структура файлов

| Файл | Назначение |
|------|-----------|
| `async_server_bot.py` | Точка входа. Обработка сообщений, создание/управление PTY-сессиями, маршрутизация команд |

| `delay_config.txt` | Базовая задержка между сообщениями (минимальная 1.0, по умолчанию 5.0) |

| `keyboard_enable.txt` | `true`/`false` — включать ли клавиатуру в VK |
| `keyboard_list.txt` | Список кнопок клавиатуры в формате `Имя (команда)` |
| `version.txt` | Текущая версия бота (выводится в debug-сообщениях) |
| `vk-interactive-bot.service` | Пример unit-файла для systemd |
| `requirements.txt` | Python-зависимости |

## 4. Архитектура и поток данных

```
Админ (VK) --сообщение--> vkbottle (Long Poll) --> handle_message()
                                                       │
                        ┌──────────────────────────────┴──────────────────────────────┐
                        │ есть активная сессия? Нет ──> get_or_create_session()       │
                        │   - os.openpty() → bash subprocess                         │
                        │   - asyncio read/write pipe на master_fd                   │
                        │   - запуск start_output_listener() (фоновая задача)        │
                        └──────────────────────────────┬──────────────────────────────┘
                                                       ▼
                                            отправка команды во writer
                                                       │
                                                       ▼
                                   [обычный режим] команда + маркер
                                   echo '' / echo "___END_OF_COMMAND___:$(pwd)"
                                                       │
                                                       ▼
                                   shell_worker: чтение PTY, ANSI-очистка,
                                   buffering, отправка в ВК (send_safe_message)
```

### Ключевые идеи реализации

- **Псевдо-терминал (PTY)**: `os.openpty()`, дочерний `/bin/bash`, обёртки через
  `asyncio.StreamReader`/`StreamWriter`. Хранится в глобальном `user_sessions[user_id]`.
- **Маркер окончания**: строка `___END_OF_COMMAND___:<pwd>` вставляется после
  не-интерактивных команд, чтобы бот знал, что вывод завершён и путь обновлён.
- **Флуд-контроль VK**: переменная `current_flood_multiplier` — при ошибках
  `flood`/`disallowed` множитель растёт (×2.5 до 10), при успехе плавно падает (−0.5).
- **Интерактивный режим** (`user_interactive_mode[user_id] = True`): весь вывод
  льётся потоком без маркера; включается для команд из `interactive_list.txt`.
- **Глобальные переменные-состояние** живут в `shell_worker.py` (это осознанное
  решение против circular-import): `user_interactive_mode`,
  `current_flood_multiplier`, `last_valid_path`.

## 5. Служебные команды (зарезервированы)

| Команда/фраза | Действие |
|--------------|----------|
| `сброс` / `reset` / `exit` | Полный сброс сессии, задержек, пути |
| `hard-reset` / `убей сессию` / `kill-session` | Жёсткое уничтожение зависшей сессии + создание новой |
| `turbo` / `турбо` | Принудительный сброс флуд-множителя на 1.0 |
| `ctrl` / `сигнал` / `ctrl+c` | Шлёт физический байт `\x03` (SIGINT) в PTY |
| `art: <команда>` | Выполняет команду в текущей папке сессии и присылает результат картинкой (PNG) |
| `🖼 ART` | Включает ART-режим: обычные команды приходят картинкой |
| `📄 Текст` | Выключает ART-режим: обычные команды приходят текстом (кроме `art: …`) |

Зарезервированные кнопки клавиатуры: `⌨️ Ctrl+C`, `📴 Off`, `💀 Hard Reset`, `🔄 Reset`, `🖼 ART`, `📄 Текст`.

## 6. Конвенции и правила кода

- **Язык**: комментарии и логи сообщений — **русский**. Тексты для пользователя
  в VK — тоже русский.
- **Версионирование**: единый источник — `VERSION = "5.4.1"` в `config_manager.py`.
  `async_server_bot.py` и `shell_worker.py` используют
  `VERSION = config_manager.VERSION`. Файл `version.txt` читается `get_version()`
  на лету и может переопределять версию, показанную в заголовках путей.
  При каждом изменении функциональности повышай `VERSION` (например `5.4.0` → `5.4.1`)
  и синхронизируй `version.txt`.
- **Единый логгер**: `log_message(level, message)` живёт в `config_manager.py`.
  Используй его вместо `print()` и вместо локального логгирования. Он пишет
  в stdout и в `bot_server.log`.
- **ART-режим**: глобальный флаг `config_manager.art_mode` (True = обычные команды
  приходят картинкой). Управляется кнопками `🖼 ART` / `📄 Текст`; проверка
  переключателей стоит в `handle_message` раньше остальных команд.
- **Комментарии-история**: принято помечать исправления вида
  `# ИСПРАВЛЕНО (vX.Y.Z): <что и зачем>` — не удаляй их, добавляй свои с новой версией.
- **Типизация**: функции помечены аннотациями (`-> str`, `-> bool` и т.п.),
  docstring'и на русском. Старайся их сохранять.
- **Обработка ошибок**: идиома `try/except: pass` уже широко используется в проекте
  для не-критичных файловых операций. Для новой логики лучше писать осмысленный
  `log_message("ERROR", ...)`, а не молчаливый `pass`.
- **Зависимости**: только то, что уже есть в `requirements.txt`, либо добавь с
  обоснованием в `AGENTS.md`/README.

## 7. Как запускать / тестировать

Локально (Windows) бот не запустишь — он завязан на Linux (PTY, `/bin/bash`,
`/root`). Проверка на деплое:

```bash
cd /root/vk-api
source venv/bin/activate
python3 async_server_bot.py        # запуск вручную
# или
sudo systemctl restart vk-interactive-bot   # через systemd
```

Логи: вывод в stdout + файл `bot_server.log` (в `.gitignore`).

**Рекомендация при внесении правок**: минимум — проверить `python3 -m py_compile`
для изменённых модулей, идеально — прогон на Linux-сервере.

## 8. Правила безопасности (критично!)

1. **Никогда не коммить `bot_config.txt`** (содержит токен и ID админов) — он в `.gitignore`.
2. `ALLOWED_ADMINS` — единственная точка допуска. Не ослабляй проверку
   `if user_id not in ALLOWED_ADMINS: return` в `handle_message()`.
3. Бот выполняет произвольные команды в bash от root. Любой рефакторинг должен
   сохранять контроль доступа и обработку `hard-reset` на случай зависания.
4. Не выводи полный токен/секреты в логи или в ответы бота.
