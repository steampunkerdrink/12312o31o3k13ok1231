# Changelog

История заметных изменений проекта.

Версия хранится в `config_manager.VERSION` и дублируется в `version.txt`.
Формат разделов: `## [версия] — дата`, подразделы Добавлено / Изменено / Исправлено.

---

## [5.16.0] — 2026-10-18

### Добавлено
- **Self-update**: команда `update` / `обновить` (только для админов) — выполняет `git pull --ff-only`
  в папке бота, проверяет, что новый код компилируется (`py_compile`; если нет — откатывает pull и
  не перезапускается), и перезапускает процесс через `os.execv` (PID сохраняется — прозрачно для
  systemd). Доступна только админам (весь обработчик под `ALLOWED_ADMINS`).

## [5.15.4] — 2026-10-18

### Изменено
- **Подсказка по склейке** (`send` / `send_base64`, несколько частей) переписана:
  - добавлено предупреждение, что **VK может переименовать части** при скачивании —
    нужно свериться с реальными именами в папке;
  - добавлен **рабочий PowerShell-вариант** склейки байтов (через `[IO.File]`), т.к.
    в PowerShell `copy` — это алиас `Copy-Item` и `copy /b A+B` там не работает;
  - для base64: `cat | base64 -d` (Linux) и `copy /b …` + `certutil -decode` (cmd).
- **`bg:<команда>`**: в ответ добавлено предупреждение — бесконечные команды (ping без -c,
  tail -f, top) забивают чат, Ctrl+C фоновую задачу НЕ убивает, для остановки — 💀 Hard Reset.

## [5.15.3] — 2026-10-18

### Исправлено
- **`send_base64` падал с «name '_send_b64_command' is not defined».** В 5.15.0 при
  рефакторинге потерялся заголовок функции `_send_b64_command`, и её тело оказалось внутри
  `_send_file_command` (из-за чего обычный `send` мог дополнительно запускать base64-ветку).
  Заголовок восстановлен; `send` и `send_base64` теперь независимые команды.

## [5.15.2] — 2026-10-18

### Исправлено
- **`send` / `send_base64`**: VK возвращал `{"error":"not saved"}` — не мог сохранить
  загружаемый документ (реальные лимиты VK ниже заявленных, особенно для больших `.txt`).
  Уменьшен размер частей: base64 `.txt` → **50 МБ**, обычный документ → **100 МБ**.
  При ошибке «not saved» бот теперь даёт вразумительную подсказку про уменьшение части.

## [5.15.1] — 2026-10-18

### Исправлено
- **Убран «мусор» в начале вывода** (в `ls -la` и др.): строки `echo __SESS_READY__`,
  `0;root@…:` и сам маркер просачивались из инициализации PTY-сессии в первый реальный вывод.
  Причина — `discard_output` пересоздавал список буфера, тогда как фоновый слушатель держал
  ссылку на старый объект → сброс не доставал реальный буфер. Теперь буфер очищается на месте.
- Также: в инициализацию сессии добавлен `PROMPT_COMMAND=''` (убирает титулы `0;root@…`),
  а в `clean_terminal_garbage` — вырезание OSC-последовательностей (`ESC ] … BEL/ST`) перед
  ANSI (порядок важен: диапазон `\\-_` в ANSI-регексе мог съесть `ESC ]` раньше времени).

## [5.15.0] — 2026-10-18

### Изменено
- **`send <путь|url>`** теперь отправляет файл **обычным документом без обфускации** —
  исходное имя/расширение сохраняется. Большие файлы режутся на бинарные части
  (`name.part1`, … по ~150 МБ) с подсказкой склейки (Linux `cat`, Windows `copy /b`).
- **`send_base64 <путь|url>`** — прежнее поведение `send` (обфускация base64 в `.txt`,
  без расширения, разбиение ~95 МБ). Обе команды принимают локальный путь или URL.
- `docs/IDEAS.md`: добавлена идея про облачные хранилища (Яндекс.Диск / Mail) для
  выгрузки крупных файлов наружу (отдельная команда `upload`).

## [5.14.10] — 2026-10-18

### Исправлено
- **`send`**: base64-кодирование большого файла больше не блокирует бота. Тяжёлая работа
  выполняется в отдельном потоке (`asyncio.to_thread`) — раньше event loop «замирал»,
  и Long Poll не отвечал, пока кодировался большой файл (выглядело как зависание).
  Добавлено логирование этапов (начало/готово) и подсказка в чате.
- Запись частей стала буферизованной (пачками по ~1 МБ вместо построчно) + фиксация
  размеров каждой части и детерминированная кодировка строк (`newline="\n"`).

## [5.14.9] — 2026-10-18

### Добавлено
- **`send`**: после успешной отправки бот **удаляет временные файлы** — сгенерированные
  `.txt`-части и (если файл качался по URL) скачанный исходник в `tmp/`. Локальный файл
  пользователя (путь на сервере) не трогается.

## [5.14.8] — 2026-10-18

### Исправлено
- **`send <url>`**: скачивание больше не отклоняет файлы крупнее 100 МБ — лимит исходного
  файла поднят до **5 ГБ** (кодирование потоковое, результат авто-разбивается на ~95 МБ
  части). Раньше файл >100 МБ падал на этапе скачивания с «файл больше 100.0 MiB».

## [5.14.7] — 2026-10-18

### Изменено
- **`send`**: base64-кодирование теперь **потоковое** (файл читается блоками по 3 МБ,
  целиком в память не грузится — можно отправлять крупные файлы).
- Если итоговый `.txt` больше **95 МБ**, он разбивается на части
  (`name.txt`, `name.part2.txt`, …), каждая отправляется отдельным документом в одном
  сообщении, с подсказкой по склейке и декоду (Linux `cat … | base64 -d`, Windows
  `copy /b …` + `certutil -decode`).

## [5.14.6] — 2026-10-18

### Изменено
- **`send <url>`**: имя отправляемого `.txt` теперь берётся из исходного имени скачанного
  файла, а не из служебного пути `dl_<id>_…` — т.е. `dl_171474445_7z2604-x64.exe.txt`
  превращалось в `7z2604-x64.txt`. Имя не выдаёт ни префикс, ни исходное расширение.

## [5.14.5] — 2026-10-18

### Изменено
- **`send`**: имя отправляемого `.txt` больше не содержит исходное расширение файла
  (например `7z2604-x64.exe.txt` → `7z2604-x64.txt`), чтобы получатель не видел тип.

## [5.14.4] — 2026-10-18

### Изменено
- **`send <путь|url>`** больше не упаковывает файл в архив: VK отклоняет архивы с
  непроверяемым содержимым (`empty_archive`, `wrong_arch_file` — в т.ч. вложенные и
  запароленные). Теперь файл кодируется в **base64** и отправляется как `.txt`
  (обычный документ, VK принимает), а содержимое скрыто кодированием. Получатель
  декодирует `.txt` обратно в файл (Linux `base64 -d`, Windows `certutil -decode`).
  Убраны зависимости от 7-Zip и функции 7z/zip-архивирования.

## [5.14.3] — 2026-10-18

### Исправлено
- **`send`**: VK отклонял запароленный 7z с ошибкой `empty_archive` (`{"file": …}` не
  возвращался, upload-сервер отвечал `{"error":"empty_archive"}`). VK распознаёт файл
  как архив по содержимому и отклоняет защищённые/нечитаемые архивы. Теперь запароленный
  7z оборачивается во внешний **обычный .zip** (незапароленный, непустой — принимается VK).
  В чат приходит `.zip`, внутри — `.7z` с паролем `123456`.

## [5.14.2] — 2026-10-18

### Изменено
- **`send`**: загрузка документа в VK переписана вручную (обход `vkbottle.DocMessagesUploader`)
  с пошаговой диагностикой. Теперь в логи пишется сырой ответ upload-сервера — при
  «file is undefined» видно, на каком шаге теряется файл: не получен upload_url,
  POST не принял файл, или ответ не содержит поле `file`. `group_id` (5.14.1) ситуации
  не решил, поэтому нужен реальный ответ сервера для точной причины.

## [5.14.1] — 2026-10-18

### Исправлено
- **`send`**: загрузка документа в VK падала с `VK error 100: file is undefined` — upload-сервер
  не возвращал `file`, потому что для бота-сообщества не передавался `group_id` в
  `docs.getMessagesUploadServer`. Теперь `group_id` резолвится через `groups.getById` (с кэшем)

  а в чат возвращается конкретная причина вместо общего сообщения.

## [5.11.7] — 2026-10-11

### Изменено
- ART-картинка теперь приходит **двумя сообщениями**: фото-превью (PNG) **и** документ (PNG).
  Причина: VK фото всегда пережимает у себя в JPEG (отсюда «зашаканенность»), а документы не трогает —
  поэтому дополнительно отдаём чёткий **PNG без потерь** (файл `art.png`).
- Убрана перекодировка в JPEG — лишняя трата времени; в PNG и фото, и документ.

## [5.11.6] — 2026-10-11

### Исправлено
- Отправка ART-картинки падала с `photo is undefined` / `file is undefined` — VK-эндпоинт
  не принял PNG. Теперь каскад: фото как **PNG** → при неудаче фото как **JPEG** (перекодировка
  на лету) → документ. То есть PNG используется, когда VK его принимает, иначе прозрачно
  откатываемся на JPEG, и лишь затем документ.

## [5.11.5] — 2026-10-11

## [5.11.2] — 2026-10-11

### Исправлено
- ART-картинку «разрывало» на командах с прогресс-барами (`git pull`, `apt`, `wget`):
  символ `\r` (возврат каретки) не обрабатывался, поэтому все обновления одной строки

## [5.10.0] — 2026-10-11

### Добавлено
- **Health-check новой PTY-сессии**: после создания бот шлёт зонд `__SESS_READY__`
  и проверяет, что bash реально читает fd; если сессия «глухая» — автоматическое
  пересоздание (до 2 попыток). Системно устраняет молчащие сессии (в т.ч. после hard-reset).
- **Подпись на ART-картинке**: `user@host:path# <команда>` сверху (caption к фото).
- **ART-настройки текстовыми командами**: `art:bg dark|light|auto` (фон) и
  `art:font N` (размер шрифта). Рендер `terminal_render` параметризован.
- **`bg:<команда>`** — фоновый запуск (не держит чат), вывод приходит по мере работы.
- **`help` / `помощь` / `?`** — список команд бота.

### Изменено
- Удалён неиспользуемый `_run_capture` (ART давно выполняется через активную сессию).

## [5.9.2] — 2026-10-11

### Исправлено
- После `HARD-RESET` во время активного ssh/интерактива бот «молчал»: новая сессия создавалась
  сразу после уничтожения старой, когда ОС ещё не освободила fd/процессы → сессия выходила
  «глухой». Теперь, как и в обычном `reset`, создание ленивое — свежую сессию поднимает
  следующая команда (этот путь стабилен).
- В ветке `HARD-RESET` не было логирования — добавлены `log_message` (уничтожение сессии
  и ожидание создания).

## [5.9.1] — 2026-10-11

### Изменено
- Убран хардкод-блок алиасов (`ls/grep/diff --color=auto`, `shopt -s expand_aliases`) из
  `init_cmd`. Сессия интерактивная и сама читает реальный `~/.bashrc`, поэтому теперь
  работают **настоящие** алиасы сервера, а не подставные. Это важно для ART: с v5.9.0
  `art:` выполняется в той же сессии → использует те же реальные алиасы, что и обычные команды.

## [5.9.0] — 2026-10-11

### Изменено
- ART теперь выполняется в контексте **активной PTY-сессии** (в т.ч. внутри `ssh`): команда
  и маркер `___END_OF_COMMAND___` пишутся в живую сессию, сырой вывод с ANSI-цветами
  захватывается и рендерится картинкой. Единая логика для ART-режима и префикса `art:` —
  отдельный `img:` не нужен.
- В init-сессию добавлены алиасы `ls/grep/diff --color=auto`, чтобы картинки из сессии были цветными.

### Добавлено
- Страховка `_capture_timeout` (60 c): если маркер не пришёл, захват снимается и шлётся `⏱`-уведомление.

## [5.8.4] — 2026-10-11

### Исправлено
- Интерактивные команды (`ssh` и др.) могли сразу завершаться/вести себя некорректно из-за
  окружения PTY-сессии. Теперь сессии назначают PTY управляющим терминалом (`TIOCSCTTY`),
  имеют размер окна `40×160` (было `0×0`) и `TERM=xterm-256color`.

## [5.8.3] — 2026-10-11

### Исправлено
- `ls` в ART-режиме оставался нецветным: команда запускалась в неинтерактивном `sh`, где
  нет алиаса `ls --color=auto`. Теперь ART-команда идёт через `bash -c` с включёнными
  алиасами (`ls`/`grep`/`diff` с `--color=auto`), поэтому цветной вывод работает.

## [5.8.2] — 2026-10-11

### Исправлено
- ART-режим падал с `[Errno 5] Input/output error`: чтение master-части PTY после закрытия
  slave дочерним процессом даёт `EIO`, а не EOF. Теперь `EIO` трактуется как конец вывода.

## [5.8.1] — 2026-10-11

### Исправлено
- После `Hard Reset` бот молчал до обычного `reset`: новая сессия создавалась слишком
  рано (через 0.05 c), пока fd/транспорт старой ещё не освободились. Теперь сессия
  снимается через `_teardown_session` (отмена + ожидание завершения слушателя) и только
  затем, с паузой, создаётся новая.

## [5.8.0] — 2026-10-11

### Добавлено
- ART-режим и команда `art:` теперь запускают команду в **PTY**, поэтому утилиты
  (`ls`, `grep`, `screenfetch`…) видят терминал и отдают ANSI-цвета — картинка
  получается цветной. VK не умеет показывать цветной текст, поэтому цвета доступны
  только в режиме картинки.

## [5.7.5] — 2026-10-11

### Исправлено
- При остановке/рестарте asyncio писал `Task was destroyed but it is pending!` для
  `run_polling` и `idle_watchdog`: обработчик SIGTERM останавливал цикл, не отменяя задачи.
  Теперь задачи корректно отменяются и дожидаются перед остановкой (без «шума»).

## [5.7.4] — 2026-10-11

### Исправлено
- При первом обращении к новой сессии приходил **дубликат** заголовка пути (сначала пустой,
  затем с выводом): инициализация сессии печатала собственный маркер окончания, и слушатель
  принимал его за завершение команды. Маркер из инициализации убран.

## [5.7.3] — 2026-10-11

### Исправлено
- Многострочный вывод иногда «склеивался» в одну строку: обработчик маркера удалял
  переводы строк из всего текста перед маркером. Теперь переводы строк сохраняются
  (срезается только хвостовой мусор). Проявлялось, когда вывод и маркер приходили
  одним куском — отсюда непостоянство.
- При `systemctl stop/restart` дочерние PTY-сессии теперь закрываются: добавлен
  обработчик SIGTERM/SIGINT (иначе bash мог остаться «висячим»).

## [5.7.2] — 2026-10-11

### Исправлено
- Вывод команды без завершающего перевода строки (например `cat` файла со значением
  `true`) терялся: приглашение bash слипалось с выводом (`trueroot@host:...#`), и очистка
  удаляла всю строку вместе с полезным текстом. Теперь при инициализации сессии
  выставляется `PS1=''` (приглашение не печатается), а очистка вырезает только вкрапления
  промпта, сохраняя остальной текст.
